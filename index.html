1什么是自然语言处理

What is Natural Language Processing

自然语言处理（Natural Language Processing，简称 NLP）是人工智能的一个分支：让计算机理解、处理、生成人类语言。它横跨计算机科学、语言学和数学——因为我们日常交流用的中文、英文是「给人设计的」，充满模糊和省略，机器处理起来远比处理表格数字困难。

1.1 理解与生成：NLP 的两大方向

  • 自然语言理解 NLU（Natural Language Understanding）：从文本里「读出」含义——分词、情感分析、意图识别、信息抽取、问答。
  • 自然语言生成 NLG（Natural Language Generation）：把含义「写成」文本——自动摘要、机器翻译、对话回复、写代码。

今天的 ChatGPT 类模型同时具备两者：先「理解」你的问题，再「生成」回答。

1.3 为什么 NLP 特别难？

通俗理解 人类理解语言靠的是「常识 + 上下文」：「苹果发布会」里的苹果是公司，「苹果很甜」里的苹果是水果——同样的词，含义由语境决定。机器没有人生经验，只能从数据里统计规律。
  • 歧义 Ambiguity：「他借我这本书」——是他借给我，还是我借给他？「咬死了猎人的狗」是狗咬死了猎人，还是猎人的狗被咬死了？
  • 同义与省略：同样问「北京到上海多远」，可以有十几种说法，还经常省略主语。
  • 长距离依赖 Long-distance Dependency：「那只我三年前在公园里捡到的猫」——「猫」和谓语可能隔着十几个字。
  • 反讽与言外之意：「这服务真是棒极了」可能恰恰是差评。

1.4 NLP 发展的三个时代

规则时代（1950s–1980s）

语言学家手写语法规则：词性、句法树、正则表达式。能处理小范围问题，但规则永远写不完，换个领域就失效。

统计机器学习时代（1990s–2010s）

从大规模语料里数数、算概率：TF-IDF、朴素贝叶斯、N-gram、隐马尔可夫模型、CRF。本课第 3–5 章就是这个时代的核心。

神经网络与预训练时代（2013–至今）

词向量 word2vec（2013）→ Transformer（2017）→ BERT/GPT（2018）→ ChatGPT（2022）。模型先在海量文本上「预训练」，再适配具体任务。本课第 6–9 章覆盖。

2文本预处理：把乱糟糟的文字收拾干净

Text Preprocessing

原始文本是「非结构化」的字符串，直接喂给模型没法用。预处理（Preprocessing）是 NLP 的地基，决定了后面一切效果——就像做菜前要洗菜、切菜。

2.1 分词：把句子切成词

分词（Tokenization）把连续文本切成最小的语义单元——词元（Token）。英文按空格和标点切就行；中文没有空格，是 NLP 的独特难题：

  • 英文："I love NLP" → ["I", "love", "NLP"]，规则简单。
  • 中文："我们爱自然语言处理" → 可能切成「我们/爱/自然语言处理」或「我们/爱/自然/语言/处理」——切法不同，含义可能不同（经典例子：「南京市长江大桥」）。

经典中文分词方法：词典最大匹配（Maximum Matching，用词典从前往后贪心匹配最长词）和统计方法（按概率找最优切分）。今天的工业标准是 jieba 分词库。

2.2 规范化：统一格式

  • 小写化 Lowercasing："Apple" 和 "apple" 是同一个词（注意：专有名词小写化可能丢信息，如 "Bush" 总统 vs "bush" 灌木丛）。
  • 去标点、去数字、去特殊符号：多数任务里 "!!!" 和 URL 是噪声。
  • 去停用词 Stop Words：删除「的、了、在、the、a、is」等高频但几乎不携带语义的词，可以大幅缩小词典、加快训练。注意：情感分析等任务里停用词可能有用，要按任务取舍。

2.3 词干提取与词形还原

英文有形态变化（run/runs/ran/running），把变体归一可以合并统计量：

  • 词干提取 Stemming：按规则暴力砍后缀——"running" → "run"，"studies" → "studi"（可能产出不是词的「伪词干」，快但糙）。
  • 词形还原 Lemmatization：查词典变回原形——"ran" → "run"，"better" → "good"（准确但慢，需要词性标注）。

输入一句话，勾选/取消各个处理步骤，观察每一步的输出变化。中文分词用的是「词典最大匹配」算法（内置一个小词典），英文词干提取是简化版规则。划掉的灰色词是被停用词过滤掉的。

  • 预处理步骤的选择必须服从任务目标，不要机械套用。

3词袋模型与 TF-IDF：文本变成数字的第一步

Bag of Words · TF-IDF

模型只会算数，所以文本必须变成向量。最朴素的想法是独热编码（One-hot Encoding）：给词典里每个词分配一个下标，每个词用「只有一位是 1、其余全是 0」的向量表示：

词下标独热向量（维度 = 词典大小）
猫0[1, 0, 0, …]
狗1[0, 1, 0, …]
苹果2[0, 0, 1, …]

独热编码有两个致命伤：① 词典几万到几十万词，向量维度爆炸且几乎全 0（稀疏 Sparse）；② 任意两个词的向量都互相垂直——「猫」和「狗」的相似度与「猫」和「苹果」完全相同（都是 0），完全不携带语义。

3.1 词袋模型：一篇文档 = 一个计数向量

词袋模型（Bag of Words，BoW）把整篇文档放进一个「袋子」：只数每个词出现了几次，完全忽略词序（所以叫袋子，不叫序列）。"猫 追 狗" 和 "狗 追 猫" 在词袋里一模一样——这是它最大的缺陷，但很多任务（如主题分类）用词频就够用了。

通俗理解 词袋模型像「数豆子」：把文档里的词当各种颜色的豆子，不看它们排列的顺序，只记录每种颜色有几颗。判断一篇文档是不是「体育新闻」，看「比赛、进球、球队」这类豆子多不多就够了。

3.2 TF-IDF：给重要的词更高的权重

词袋的毛病：每篇文档里「的、是、the」这类词次数都最多，却几乎不含信息。TF-IDF 修正这一点——一个词越在这篇文档里频繁出现、越少在其他文档出现，权重越高：

词频 TF（Term Frequency，本文档内的热度）： tf(t, d) = 词 t 在文档 d 中的出现次数文档 d 的总词数
逆文档频率 IDF（Inverse Document Frequency，全局的稀缺度）： idf(t) = log N1 + df(t)
TF-IDF 权重（两者相乘）： w(t, d) = tf(t, d) × idf(t)

其中 N 是文档总数，df(t) 是包含词 t 的文档数（分母 +1 防止除零）。解读：出现在所有文档里的词 df=N → idf≈log(1)≈0 → 权重归零；只出现在极少数文档里的词 → idf 大 → 是「特征词」。

3.3 文档相似度：余弦相似度

文档变成 TF-IDF 向量后，「两篇文档像不像」用它们向量的夹角衡量——夹角越小越像。这就是余弦相似度（Cosine Similarity）：

余弦相似度（值域 [−1, 1]，越接近 1 越相似）： cos(A, B) = A·B||A|| · ||B|| = ni=1Σ aibi√ni=1Σai² √ni=1Σbi²

除以两个向量的模长（Norm）是为了归一化：只看「方向」不看「长度」，这样长文档和短文档也能公平比较。

4朴素贝叶斯：史上最经典的文本分类器

Naive Bayes Classifier

朴素贝叶斯（Naive Bayes）从贝叶斯定理（Bayes' Theorem）出发，是垃圾邮件过滤的祖师爷，也是入门概率模型的完美教材。先回顾条件概率与贝叶斯公式：

贝叶斯定理（由条件概率 P(A|B)=P(A∩B)/P(B) 推出）： P(A|B) = P(B|A) · P(A)P(B)
  • 先验概率 Prior P(A)：还没看证据时，事件本身的概率（比如 20% 的邮件是垃圾邮件）。
  • 似然 Likelihood P(B|A)：在 A 成立的前提下观察到 B 的概率（垃圾邮件里出现「免费」的频率）。
  • 后验概率 Posterior P(A|B)：看到证据 B 后，更新过的概率（看到「免费」后，这封邮件是垃圾邮件的概率）。
  • 证据 Evidence P(B)：归一化常数，比较两类时可以被约掉。
通俗理解 医生先根据人群发病率给一个「基础判断」（先验），再根据化验单（证据）修正判断，得到「你现在得病的概率」（后验）。贝叶斯定理就是这个修正公式。

4.1 「朴素」在哪：条件独立假设

要算 P(w₁, w₂, …, wₙ | spam)（一堆词同时出现的联合概率）太难了。朴素贝叶斯假设各词条件独立（Conditional Independence）——给定类别后，词与词互不影响：

朴素假设 + 分类规则（∝ 表示成正比，比较两类时 P(w) 可约掉）： P(spam | w₁…wₙ) ∝ P(spam) · P(w₁|spam) · P(w₂|spam) ⋯ P(wₙ|spam)

这个假设在现实中「明显不对」——「免费」和「中奖」经常一起出现，并不独立。但神奇的是：即使假设不成立，朴素贝叶斯的分类结果往往依然很好（它需要的只是把概率算对大小顺序）。这就是工程中「错的模型，对的结果」的经典案例。

4.2 两个工程细节

  • 取对数防下溢：几百个词的概率相乘会小到浮点数溢出（10⁻³⁰⁰⁰）。取对数后乘法变加法，比较结果不变：log P = log P(spam) + Σ log P(wᵢ|spam)。
  • 拉普拉斯平滑 Laplace Smoothing：训练集里没见过的词概率会是 0，一个 0 把整个乘积归零。给每个计数 +1（分母 +词典大小 V）兜底：P(w|c) = (count(w,c)+1)/(count(c)+V)。

本章小结
  • 贝叶斯定理：后验 ∝ 先验 × 似然；朴素 = 假设词条件独立。
  • 实现三件套：log 空间计算、拉普拉斯平滑、先比较后归一化。
  • 即使独立性假设不成立，朴素贝叶斯作为「文本分类基线」依然非常能打。

5N-gram 语言模型：让机器「接话」

N-gram Language Models

语言模型（Language Model，LM）回答两个问题：①「这句话有多像人话？」——给任意词序列打一个概率；②「下一个词最可能是什么？」——算条件概率 P(下一个词 | 前面的词)。输入法联想、语音识别纠错、机器翻译选句，甚至今天的 GPT，本质上都在做这两件事。

先忘掉公式N-gram 语言模型的核心思想土得不能再土：「数数，然后做除法」。想知道「爱」后面最可能跟什么词？把语料里所有「爱」找出来，数一数它右边各出现了什么词——出现最多的，就是模型认为最可能的接话。这就是全部秘密。

5.1 先会数数：Bigram 计数（本章核心，务必看懂）

用 3 句话的迷你语料手把手数一遍：

语料（共 3 句，词之间用空格分隔）： 我 爱 吃 苹果 我 爱 学习 他 爱 吃 西瓜 问题：已知上一个词是「爱」，下一个词最可能是谁？ 数数过程： ① 在语料里圈出所有「爱」→ 共出现 3 次（作为「上一个词」的位置） ② 看每个「爱」右边跟着谁：第 1 句→「吃」、第 2 句→「学习」、第 3 句→「吃」 ③ 汇总：吃 ×2，学习 ×1 结论：P(吃|爱) = 2/3 ≈ 0.67，P(学习|爱) = 1/3 ≈ 0.33，其余为 0。 「爱」后面接「吃」的可能性最大——机器就是这么「学会接话」的。

5.2 动手数一数：Bigram 计数工厂

演示 4+ · Bigram 计数工厂（数数 → 除法 → 概率）

点击任意词，语料中所有该词的「上一个词位置」会高亮为黄色、它右边的后继词高亮为绿色；下方自动生成计数表和概率（含加一平滑）。点「苹果」试试：它只出现在句尾，作为「上一个词」出现了 0 次——这就是数据稀疏。

5.3 概率 = 数数 ÷ 数数（极大似然估计）

Bigram 概率：分子是「两词一起出现的次数」，分母是「前一个词出现的次数」 P(wi|wi−1) = count(wi−1, wi)count(wi−1)

套用上面的例子：P(吃|爱) = count(爱, 吃) ÷ count(爱) = 2 ÷ 3 = 0.67。这种「让语料出现概率最大」的估计方法叫极大似然估计（Maximum Likelihood Estimation，MLE）——说白了就是「用实际出现的频率当概率」。

但有个致命问题：语料里没见过的组合概率是 0（数据稀疏 Data Sparsity）。比如 P(苹果|爱) = 0÷3 = 0——可「我爱苹果」并不是病句！一个 0 会让整句概率连乘后变成 0。于是要平滑（Smoothing），最经典的是拉普拉斯加一平滑（Add-one Smoothing）：

加一平滑：所有计数 +1，分母 + 词典大小 V（保证概率仍然加起来等于 1） P(wi|wi−1) = count(wi−1, wi) + 1count(wi−1) + V

例：本语料词典 V = {我, 爱, 吃, 苹果, 学习, 他, 西瓜} 共 7 个词。P(吃|爱) = (2+1)/(3+7) = 0.3；P(苹果|爱) = (0+1)/(3+7) = 0.1——从 0 变成了 0.1，「没见过」也有了一点点可能性。

5.4 整句概率：链式法则 + 马尔可夫假设

「我 爱 吃 苹果」整句的概率怎么算？用链式法则（Chain Rule）拆成条件概率连乘：

链式法则（精确但不可行——历史越长越数不过来）： P(w₁…wₙ) = P(w₁)·P(w₂|w₁)·P(w₃|w₁w₂)⋯P(wₙ|w₁…wₙ₋₁)

最后一项要看「前面所有词」，这种组合在语料里几乎数不到。N-gram 引入马尔可夫假设（Markov Assumption）：下一个词只和最近的 n−1 个词有关。二元模型（Bigram）只回看 1 个词，于是整句概率 ≈ P(我)·P(爱|我)·P(吃|爱)·P(苹果|吃)——每一项都能用 5.3 的数数除法算出来。

5.5 困惑度：模型的「惊讶程度」

语言模型好不好，用困惑度（Perplexity，PPL）衡量：模型对测试文本「平均每个词有多惊讶」，越小越好。直觉：PPL = 100 意味着平均每个词像是在 100 个候选里瞎猜；PPL = 10 意味着基本十猜九中。

困惑度（N 为词数）： PPL = 2 −1N Ni=1Σ log₂ P(wi|context)

6词向量：让机器「看见」语义

Word Embeddings · Word2Vec

还记得独热编码的问题吗——「猫」和「狗」的相似度与「猫」和「苹果」一样。词向量（Word Embedding，也叫词嵌入）把每个词表示成一个稠密、低维、连续的向量（比如 300 维），让语义相近的词在向量空间里挨得近。

6.1 分布式假设：看一个词交什么朋友

语言学名言：「You shall know a word by the company it keeps」（观其伴而知其词）。分布式假设（Distributional Hypothesis）认为：上下文相似的词，语义也相似。「猫」和「狗」前面的动词总是「喂、遛、养」——于是它们的向量自然靠近。词向量不是人定义的，而是从大量文本中「统计」出来的。

6.2 Word2Vec：两个经典结构

Word2Vec（2013，Google）用浅层神经网络在大语料上训练词向量，两种结构互为镜像：

训练目标：Skip-gram 用中心词预测窗口内的上下文词，输出层做 Softmax 分类。词表太大（几十万）时 Softmax 太慢，实际用负采样（Negative Sampling，只随机抽几个「反例」词来训）提速。

6.3 词向量的神奇性质：向量算术

词向量最著名的性质：语义关系 ≈ 向量方向的差。经典结论：

词向量类比（Word Analogy）： vec(国王) − vec(男人) + vec(女人) ≈ vec(王后)

「国王 − 男人」抽出了「王权/性别」的方向向量，把它加到「女人」上就得到「王后」。同样的方向差可以迁移：「北京 − 中国 + 日本 ≈ 东京」（首都方向）。这说明模型确实「学懂」了关系结构。

6.4 动手玩：词向量空间

演示 5 · 词向量空间可视化（2D 降维投影）

真实词向量有几百维，这里用 2D 投影示意其结构：同色=同类词（动物/水果/城市/人物/动作/科技/自然），距离近=语义近。点击任意词看它的最近邻；先在右侧选一个「类比对」（如 国王→王后），再点任意词，系统计算「A − B + C」落在哪个词附近——这就是词向量类比。

点击左侧画布上的词开始探索……
进阶Word2Vec 是静态词向量：一个词永远同一个向量，无法区分「苹果公司」和「苹果水果」。BERT 之后的上下文词向量（Contextual Embedding）让同一个词在不同句子里有不同的向量，彻底解决了多义词问题。
本章小结
  • 词向量把语义编码进几何空间：语义近 → 距离近，关系 ≈ 向量差。
  • 训练依据是分布式假设：上下文相似的词语义相似（CBOW / Skip-gram）。
  • 词向量类比（国王−男人+女人≈王后）是「模型理解语义」的经典证据。

7序列模型：RNN 与 LSTM

Recurrent Neural Networks · LSTM

文本是变长的序列，词序携带信息（「猫追狗」≠「狗追猫」）。普通前馈网络要求固定长度的输入，也没法处理「第 3 个词影响第 30 个词」的长距离关系。循环神经网络（Recurrent Neural Network，RNN）为此而生。

7.1 RNN：带记忆的循环

RNN 的核心：一个细胞单元（Cell）不仅吃当前输入，还吃自己上一步的状态——按时间展开后是一条链：

RNN 的更新公式（Wₕ 是「记忆」权重，三步共享同一组参数）： ht = tanh( Wx·xt + Wh·ht−1 + b )

每个时刻的隐藏状态 hₜ 是「到目前为止读到的内容」的压缩记忆。训练时梯度沿时间链回传（Backpropagation Through Time，BPTT），链一长梯度连乘会指数级衰减——梯度消失（Vanishing Gradient）：第 30 个词的错误几乎传不回第 3 个词。

7.2 LSTM：给记忆装上「闸门」

长短时记忆网络（Long Short-Term Memory，LSTM）解决长距离遗忘问题。它有一条贯穿始终的「传送带」——细胞状态（Cell State），三扇门（Gate）决定信息的去留：

门英文作用类比
遗忘门Forget Gate决定丢掉旧记忆的哪些部分清理过时的笔记
输入门Input Gate决定把新信息的哪些部分写进记忆摘抄新要点
输出门Output Gate决定此刻输出记忆的哪些部分发言时调用笔记

门 = 一个 Sigmoid（输出 0~1）× 一条信息流，0 关 1 开。因为乘法链上有了「选择性放行」，梯度可以畅通地传播很远。

7.3 Seq2Seq：序列到序列

机器翻译需要「吃一句话，吐另一句话」。序列到序列模型（Sequence to Sequence，Seq2Seq）用两个 RNN：编码器（Encoder）把输入句子压成一个固定长度的「上下文向量」，解码器（Decoder）再从这个向量逐词生成译文：

Seq2Seq 的瓶颈：无论输入多长，都要塞进一个固定大小的向量 c——长句子会「装不下、记不住」。下一章的注意力机制就是来解决这个问题的。

本章小结
  • RNN 用循环结构处理变长序列，按时间展开 = 同参数反复使用。
  • 长序列训练会遇到梯度消失；LSTM 用三门（遗忘/输入/输出）保护长距离记忆。
  • Seq2Seq = 编码器压缩 + 解码器生成，固定向量是它的瓶颈。

8注意力机制与 Transformer：NLP 的转折点

Attention · Transformer

8.1 注意力：让模型学会「看哪里」

人类翻译长句时不会把整句话背下来再翻译，而是每写一个词，回头看一眼相关的原文位置。注意力机制（Attention Mechanism）把这个直觉做成数学：对每个输出位置，用「查询」在所有「键」上打分，Softmax 归一化成权重，再对「值」做加权平均。

通俗理解 查字典（查询 query）时，你把问题（Q）和所有词条（键 key）比对，找到最相关的那几条，然后集中读它们的解释（值 value）。权重越大的位置，读得越仔细。
注意力公式（√d 用于防止点积过大导致 Softmax 饱和）： Attention(Q, K, V) = softmax( QKT√dk ) · V
  • Q 查询 Query：我现在想找什么？
  • K 键 Key：每个位置「是什么」（供比对）。
  • V 值 Value：每个位置「有什么」（被加权取走的内容）。

自注意力（Self-Attention）里 Q、K、V 都来自同一句话：每个词和句子里所有词两两打分——「它」指代谁、「bank」是银行还是河岸，全靠这些分数决定。

8.3 Transformer：注意力 = 一切

2017 年的论文《Attention Is All You Need》提出 Transformer，彻底抛弃 RNN 的串行循环，整个网络由多头自注意力（Multi-Head Attention）和前馈网络堆叠而成。三大优势：

  • 并行训练：RNN 必须一个词接一个词地算；Transformer 全句同时算，训练快得多。
  • 长距离无障碍：任意两个词直接「对话」，距离恒为 1 步，没有梯度消失。
  • 可扩展性：堆更多层、更大数据，性能持续增长——GPT 从 1.1 亿参数长到万亿参数，靠的就是这个架构。

两个细节：① 注意力本身对词序不敏感，所以要位置编码（Positional Encoding）把「第几个词」的信息加进输入；② 「多头」= 把注意力拆成多个子空间并行计算（有的头管语法、有的头管指代……各看各的，最后拼接）。

历史地位Transformer 之后诞生了两大家族：BERT（双向编码器，擅长理解）和 GPT（单向解码器，擅长生成）。今天几乎所有大模型都是 Transformer 的变体——「Attention Is All You Need」名副其实。
本章小结
  • 注意力 = Q 和 K 打分 + Softmax + 对 V 加权平均，让模型动态「看重点」。
  • 自注意力让句子内部词与词直接两两交互，解决长距离依赖。
  • Transformer 用纯注意力架构实现并行训练、无限扩展，是当代 NLP 的地基。

9预训练大模型时代：GPT 是怎么来的

Pre-trained Language Models · LLMs

9.1 核心思想：先「读万卷书」，再「干一行」

传统做法是每个任务从零训练一个模型，标注数据又贵又少。预训练（Pre-training）的思路：先在海量无标注文本上训练一个通用语言模型（读遍全网文本，学会语法、常识、推理的统计规律），再针对具体任务微调（Fine-tuning）或直接提示（Prompting）。就像先上完基础教育，再学一门手艺——基础越扎实，学手艺越快。

9.2 两大预训练范式

一个经典例子（完形填空）：「今天天气很___，我们去公园野餐吧」→ 模型根据上下文填「好」。GPT 式的训练则是不给空格，只给「今天天气很」，让模型猜下一个字——猜得越准，学到的知识越多。

  • 预训练让模型「什么都知道一点」，但它只会续写，不会「回答问题」。
  • 指令微调（Instruction Tuning）：用「问题→答案」的示范数据训练，教会模型「听懂人话、按指令办事」。
  • RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）：让人对多个回答排序打分，模型学习「有用的、诚实的、无害的」回答偏好——这就是 ChatGPT 比原始 GPT-3 好用得多的关键。

10NLP 任务怎么打分

Evaluation Metrics

10.1 分类任务：沿用经典指标

文本分类（垃圾邮件、情感分析）直接用混淆矩阵与精确率/召回率/F1（同机器学习课第 12 章）。类别不平衡时优先 F1，而不是准确率。

10.2 生成任务：BLEU 与 ROUGE

翻译和摘要的「标准答案」不止一种，逐字比对太苛刻。BLEU（Bilingual Evaluation Understudy）的思路：统计机器译文里有多少 n 元词组（n-gram）也出现在参考译文中，再乘一个惩罚翻译过短的系数：

BLEU（简化版；pₙ 是 n-gram 精确率，BP 惩罚过短译文，r 参考长度 / c 候选长度）： BLEU = BP · exp( 4n=1Σ 14 ln pn )    BP = min(1, e1−r/c)
  • BLEU：偏重精确率（机器说的词有多少是对的），机器翻译标配。
  • ROUGE（Recall-Oriented Understudy for Gisting Evaluation）：偏重召回率（标准摘要里的要点被覆盖了多少），文本摘要常用。

10.3 语言模型：困惑度

语言模型用困惑度（Perplexity，第 5 章）：模型对测试文本越「不惊讶」，PPL 越低。GPT-2 在英文维基上 PPL ≈ 18，意思是平均每个词像从 18 个候选里猜。

10.4 大模型时代的新玩法

  • LLM-as-a-Judge：用一个强模型给另一个模型的回答打分（一致性、帮助性、安全性），逐渐成为主流。
  • 人工评测：仍然最可靠也最贵；排行榜（如 Chatbot Arena 的 Elo 评分）用群众投票给模型排名。
  • 任务匹配第一原则：指标必须和业务目标一致——客服场景更怕「答错」（看精确率），推荐场景更怕「漏推」（看召回率）。
本章小结
  • 分类看 F1；翻译看 BLEU（精确率导向）；摘要看 ROUGE（召回率导向）。
  • 语言模型看困惑度（越低越好）。
  • 生成质量最终要人来把关，指标只是辅助筛选。

11.4 新手常见误区

误区真相
「中文必须用 jieba 分词后才能进模型」老一代模型（TF-IDF/BERT）需要；现代大模型自带分词器（BPE），把文本切成 token，不需要预先分词

「模型越大越好」小任务用小模型更快更省；先把问题定义清楚、数据洗干净
「大模型什么都知道」它会幻觉、知识有过期时间；关键场景用 RAG 检索 + 人工审核
「NLP = 调 ChatGPT API」理解底层原理才能设计提示词、排查问题、评估效果——这正是本课的目的
